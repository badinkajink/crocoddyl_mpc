Command transitions and disturbed recovery

18 October 2026 · Review completed 19 October 2026 · Baseline a83ac6c

Nominal recovery passes at 8.530 s, 3.330 s after the release request. Both pulse recoveries fail by 9 s: maximum post-release sole displacement is 8.424 mm, against a 5 mm screen, and gripper contact returns after release. A first-command force-feasibility guard accepts both releases and produces identical trajectories to scheduled release. Independent review confirms the four-rollout result with 455 numerical checks and inspection of all four video frame sequences. The guard's abort branch remains unexercised; the correction remains opt-in.

Terms and metrics

Brace onset requires both feet above 5 N vertical load and robot table load above 20 N for 0.3 s. Reach onset adds hand error below 30 mm. Standing recovery requires 0.3 s of both feet loaded, robot table load below 5 N, joint speed below 0.1 rad/s, wrist speed below 0.03 m/s, standing joint root-mean-square error below 0.1 rad, base height within 50 mm of standing, sole displacement below 5 mm since the release request, and sole tangential speed below 0.02 m/s. These are simulation screens, not hardware limits.

Sole displacement is the maximum three-dimensional sole-origin motion, referenced to the first logged sample at or after the release request. The wrist point is the brace-side wrist-yaw link origin; the hand point is the reaching site. Slip is tangential sole speed while vertical load exceeds 5 N. Tracking is root-mean-square commanded minus physical joint position. Acceleration uses velocity differences at 2 ms. Force excess is positive violation of a model cone row: N for the first five rows and N m for the remaining foot rows. Forces are world-aligned at each contact origin. Policy p95 is the 95th percentile compute time, including solve, projection and transition work, excluding scoring. The control deadline is 20 ms. The passive object's 2.943 N table load is excluded from robot support.

Comparison and command schedule

Both versions retain the previous executable-torque projection and the same seed-17 estimated-state path. The target changes from x=1.06 m to 1.08 m at 4 s, with unchanged height 0.9982 m and table height 0.885 m. The earlier 90 N world +y reaching-wrist pulse is applied from 4.5 to 4.8 s. At 5.2 s, a 35-node feet-only return problem uses the existing standing costs and previous solution as its initial guess. Its first executable command is tested; the baseline always releases, while the guard rejects an infeasible projection and would regulate the current estimated braced posture toward zero velocity. Every horizon is 35 nodes at 0.02 s. No true pose or contact force enters either policy.

The saved hypothesis requires the guarded controller to finish supported at rest in both conditions without increasing sole motion. The disturbed result fails that screen. No projection rejection occurs, so the abort implementation has no rollout validation. The guard evaluates a first command; it neither detects physical release nor guarantees the later contact schedule. Release evaluation and the issued first return solve are two consecutive solver calls at the transition; policy latency includes both.

Transfer limitations

Nominal standing recovery is supported in this simulation; disturbed recovery fails despite a feasible first release command. The prescribed feet-only schedule omits renewed gripper support. Synthetic base-pose bias and ideal joint/velocity channels remain the observation assumptions. Hardware needs synchronized estimated state, encoders, issued commands and torque/current, independent sole motion, contact geometry and load, friction/compliance and transport delay. No physical hardware action was performed.

Future work

A later contact-state transition experiment should retain the same 90 N pulse, +20 mm command and scheduled-return baseline in studies/20261018_cmpc_command_recovery.py. Test whether estimated motion and support checks before release reduce the 8.42 mm right-sole displacement and prevent renewed gripper load. Failure to finish supported at rest under the same criteria would reject that correction. The present checkpoint requires no further rollout; its abort branch and command-interval force validity remain unvalidated.
