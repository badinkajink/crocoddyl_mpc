Terms and metrics. MPC means model predictive control. A world-frame change expresses the same robot, table, target and contact references in new coordinates. A base-only error changes the estimated robot position relative to those references. Each difference below is the largest absolute component across the same 35 state/control samples, expressed back in the original plan frame. Contact residual is predicted contact position minus its reference, in mm; foot orientation residual is relative rotation, in rad. Base linear acceleration uses Pinocchio body coordinates, in m/s²; angular and joint acceleration uses rad/s². Contact force uses N, moment uses N m. Normal force is the world-z component, positive upward; tangential force is the horizontal norm. First torque is requested feedforward torque, before actuator realization. Cone violation is positive excess outside a friction or wrench-cone interval, with N for force rows and N m for moment rows. Centre-of-pressure margin is the smallest distance inside the predictor's 200 × 80 mm support rectangle, in mm. RSS is peak resident memory.

Measured failure and hypothesis

The preceding foot-motion experiment measured 78.460 mm left-sole displacement under a 90 N lateral wrist pulse, with tensile predicted contact forces. Its estimated-state path includes a synthetic base bias. This experiment tests whether coordinate inconsistency could explain prediction differences before attributing them to estimation error.

The hypothesis predicts unchanged contact geometry, acceleration and requested torque under a consistent horizontal frame change. The test uses a 100 mm x translation and −70 mm y translation, first alone and then with 0.47 rad yaw. These are coordinate-test choices. The separate +10 mm world-x base error follows the earlier sensing study's assumed scale; hardware measurements have not established that error distribution.

The input is the saved nominal estimated observation at 4.50 s: MuJoCoPlant.read → default_sense(seed=17) → State → policy → pred_x_est. Every control comparison resets to the same archived-plan warm start and performs one BoxFDDP iteration at hold index 165. The horizon remains 35 nodes at 0.02 s, spanning 0.70 s. The native contact comparison evaluates all 35 resulting state/control pairs with transformed references. The complete objective is evaluated through the adapter in the original plan frame.

Scene and velocity conventions

plan_frame_control validates the table pose, target, feet and brace references against a supplied transform, converts the estimated state to the archived plan frame, and returns the predicted state in the external frame. Leaving any one scene component in the old frame was rejected in all four checks. The adapter requires a known transform and preserves the existing warm-start frame. It cannot infer an unknown base bias.

The existing table keep-out builder accepts world-aligned boxes, and the foot wrench-cone axes use the plan frame. Converting the entire problem to that frame preserves these axes. The separate native dynamics check transforms contact models and evaluates table distances in the rotated table frame. Installed Crocoddyl 3.2.1 source confirms that these LOCAL_WORLD_ALIGNED forces and moments use world axes at each contact origin; rotating their components back requires no change of moment origin.

MuJoCo free-joint linear velocity uses world axes and angular velocity uses body axes. Pinocchio uses body axes for both. The bridge rotates only the linear channel. A nonzero six-axis probe gives a bridge difference of 3.47×10⁻¹⁷ and configuration-integration error of 6.41×10⁻¹⁵ at a 1 μs interval. Deliberately rotating the angular channel gives 0.1317 rad/s error. Independent MuJoCo kinematics gives at most 1.23×10⁻¹⁵ m site-transform error, zero table-centre error and 1.12×10⁻¹⁶ rotation-matrix error.

The second numerical job caught an error in this probe: qpos[34:] belongs to the object, while the table is a static body. Moving the object left a 401 mm table-coordinate error. The final probe transforms the static table body in memory and restores it afterward. The raw archive preserves that failed check and its correction. No model file changed.

Transfer assessment

Coordinate consistency passes for the tested hold state. Relative base error remains a separate geometry error, and force feasibility remains unresolved. This checkpoint takes no plant timestep, so slip, motion rates, physical tracking and recovery retain their preceding measurements or remain untested. The preceding page provides labelled 1× videos with simulation timestamps. No new behavior claim or video is produced here.

Future work

The next motion_transfer experiment should audit the first 0.5 s combined position, velocity and feedforward servo input, then compare the original zero-velocity-weight approach with an opt-in re-solved velocity-regularized approach at the same estimated state and servo initialization. The hypothesis is that the original approach contributes to the measured 3.308 rad/s joint-speed and 226.1 rad/s² acceleration peaks. It fails if the peaks do not decrease or support and reach deteriorate. Command clipping and tracking error must be reported separately. The driver schedules that experiment.

Hardware transfer still requires synchronized estimated base pose and velocity with frame definitions and calibration, independent sole motion, encoders, commanded and measured actuator torque/current, and surface-friction measurements. Recovery needs a separate contact schedule and validation. This coordinate test supplies no hardware performance measurement.
