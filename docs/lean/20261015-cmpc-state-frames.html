Implementation findings

croco_bridge.mj_to_pin_v rotates only base linear velocity into body coordinates. MuJoCo uses world coordinates for free-joint linear velocity and body coordinates for angular velocity; Pinocchio uses body coordinates for both. The proposed check compares their configuration integration using a nonzero six-axis velocity probe. That numerical comparison has not run.

croco_geom.table_box rejects a table whose orientation differs from world axes. The fused table keep-out cost also accepts a centre and half extents without a rotation. Foot wrench cones use identity orientation. Consequently, a complete coordinate change must include the objective's axes. The new adapter validates the supplied table pose, target and contact references against one known transform, then invokes the existing controller in the plan frame. It does not estimate the transform or correct unknown base bias.
